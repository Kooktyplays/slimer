# Slimer

A procedurally generated top-down forest roguelike. Godot 4.4.1.

Endless: a mini-boss every 5 waves, a major boss every 20, forever. Death
resets the run and keeps your Essence.

## Running it

Open `game/` in Godot 4.4.1, or from the command line:

```bash
"$HOME/Downloads/Godot.app/Contents/MacOS/Godot" --path game
```

## Shipping

`RIGHTS.md` and `STEAM.md` in the parent folder cover the commercial release:
what needs licence clearance before selling, and the full Steamworks process.
`./tools/steam_build.sh` produces the depot layout Steam expects.

## Building downloadable versions

```bash
./tools/build.sh            # macOS, Windows, Linux and web
./tools/build.sh macos      # or one at a time
```

Output lands in `build/`:

| Platform | Output | Size |
| --- | --- | --- |
| macOS | `build/macos/Slimer.app` (+ `Slimer-macos.zip`) | 177 MB / 62 MB zipped |
| Windows | `build/windows/Slimer.exe` (single file) | 100 MB |
| Linux | `build/linux/Slimer.x86_64` (single file) | 73 MB |
| Web | `build/web/` | 49 MB |

The macOS app is a universal binary (Intel + Apple Silicon) and **ad-hoc
signed** — Apple Silicon refuses to launch arm64 code with no signature at
all, so this is required, not optional.

Ad-hoc is not the same as notarised. It runs fine on the machine that built
it, but anyone who *downloads* it gets macOS quarantine and a "damaged and
can't be opened" dialog. They can bypass it with:

```bash
xattr -dr com.apple.quarantine /Applications/Slimer.app
```

Removing that warning properly needs an Apple Developer account ($99/yr) to
sign and notarise. Windows shows a similar SmartScreen warning without a code
signing certificate; Linux has no equivalent gate.

Universal doubles the macOS size. `binary_format/architecture="arm64"` in
`export_presets.cfg` halves it if Intel Macs don't matter.

The web build needs to be served over HTTP, not opened as a file:

```bash
cd build/web && python3 -m http.server 8777
```

## Controls

| Action | Key |
| --- | --- |
| Move | WASD / arrows |
| Aim | Mouse |
| Shoot | Left click |
| Reload | R |
| Ability 1 | Space / Right click |
| Ability 2 | Shift / E |
| Continue (shop) | F |
| Pause | Esc |
| Screenshot | F9 |

All of these are rebindable in Settings -> Controls, keyboard/mouse and
gamepad side by side. Controllers are supported throughout: left stick moves,
right stick aims, and on-screen prompts switch to controller glyphs
automatically.

## Layout

```
assets/       sprites, music, synthesized sfx, shaders
autoload/     Events, Save, Pools, Audio, Game, DebugCapture
data/         all tuning and content tables (balance, enemies, bosses, ...)
world/        forest generation, wave controller, run controller
actors/       player, enemy, pickups, bosses
weapons/      gun and projectile
abilities/    ability controller and the abilities with their own scenes
ui/           HUD, menus, shop
fx/           pooled hit/death/telegraph effects
tests/        logic tests, headless simulation, visual pass, perf test
tools/        asset generation scripts (Python)
```

Two ideas carry most of the design:

**Difficulty is a threat budget, not an HP multiplier.** Each wave gets a
budget; each enemy type costs threat. Late waves buy more enemies, nastier
types and elite modifiers. Per-wave stat growth is capped hard
(`Balance.hp_scale` tops out at 3.2x) so wave 40 is a different fight rather
than the same fight with longer trigger pulls.

**Colour is a promise.** `data/enemy_types.gd` declares colour, behaviour and
stats in one entry, so a red slime is always the slow one that hits hard.

## Regenerating assets

Art and sound are generated by scripts, not hand-placed binaries, so they can
be re-derived and tweaked:

```bash
cd game
python3 tools/copy_assets.py   # copy the pack + music (originals untouched)
python3 tools/gen_art.py       # 87 sprites: props, bosses, UI, ground tiles
python3 tools/gen_sfx.py       # 46 wavs: sfx + tempo-matched music layers
```

`tools/gen_art.py` also slices the pack's potion files, which are 3x3 sprite
sheets rather than single bottles.

## Tests

```bash
G="$HOME/Downloads/Godot.app/Contents/MacOS/Godot"

./tools/check.sh                                        # boots clean, no script errors
$G --headless --path . -- tests                         # ~1450 logic assertions
$G --headless --path . --script res://tests/test_forest.gd   # 200-seed generation sweep
$G --headless --fixed-fps 60 --path . -- sim            # plays 26 waves and asserts the loop
$G --path . --resolution 1600x900 -- perf               # frame timing under a full wave
$G --path . --resolution 1600x900 -- visual             # screenshots every game state
```

`sim` is the important one. It drives the real run scene with real input
through 22 waves — past three mini-bosses, the major boss at 20, four shops,
the elite unlock and every enemy colour — then kills the player and checks
that the run resets while permanent unlocks survive. Adding `verbose` prints a
state dump every 600 frames, which is how the softlocks got found.

The bot is given a damage assist and topped-up health on purpose: the test is
about whether the loop wedges, not whether a script can out-shoot wave 22.

Screenshots land in `~/Library/Application Support/Godot/app_userdata/Slimer/shots`.

All test entry points set `Save.disable_writes`, so running them never touches
a real save file.

## Two things worth knowing before changing them

**Bullets do their own collision.** `weapons/projectile.gd` sweeps its circle
along the segment it travels each physics frame instead of using Area2D's
`body_entered`. The signal only fires on *entry*, which silently drops
point-blank shots (the bullet spawns already overlapping) and fast ones (it
steps over the target). The sweep also turned out cheaper than 90 monitoring
areas in the broadphase.

**Foliage animates from `anim_time`, not `TIME`.** Shader `TIME` keeps running
while the SceneTree is paused, so a paused game still had every tree swaying.
`Game` advances the `anim_time` shader global and stops when paused. Any new
animated shader should use it too.

## Notes

* On exit Godot reports "1 resource still in use" for the music stream. It is a
  shutdown-ordering artifact — the audio server stops releasing playbacks
  before autoloads are torn down — and has no effect while the game runs.
  `tools/check.sh` filters it and fails on anything else.
* `2d-project-assets/` and the root `.mp3` files are the original pack and are
  only ever read from.
